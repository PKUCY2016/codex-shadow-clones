# 使用、排障与数据保留

## 第一次运行

按 [README](../README.md) 检查环境并运行离线测试，然后 `python3 launch_shadow.py`。原实例默认取 `~/.codex`。创建分身会复制项目入口与配置并导入本地历史，然后打开独立窗口；项目较多时需要等待，面板会显示工作进度。

各分身使用独立登录。第三方插件、MCP 服务的连接可能仍需要你在对应分身确认。多个窗口操作的是同一份项目代码，给并行任务划分不同文件或使用自行管理的 worktree。

菜单栏只显示忍者头像。关闭管理网页或浏览器后，菜单栏与后台监控继续运行；点击忍者头像可重新打开管理面板。需要退出菜单栏时，打开忍者菜单后按 ⌘Q，或点击“退出菜单栏（保留分身与监控）”。在浏览器中按 ⌘Q 退出的是浏览器。

## 更新快照

点击“统一同步历史”汇总所有实例。目标仍在运行时只排队；退出后监控会补齐。更新完成后重新打开目标，以读取最新数据库与侧边栏状态。

新增表示新导入的任务，更新表示已有快照的连续追加；分支表示为独立进展创建的副本；不支持表示分页依赖等类型未合并，失败表示源文件或导入条件不满足。partial 是部分成功，不能当作完整备份。当前回合需要结束或中止后才进入下一次快照。

同步项目与配置是另一个操作，源配置优先，会备份覆盖前的目标配置。配置不做双向同步；历史开启定期汇总后，也能写回已退出的原实例。

## 常见情况

| 现象 | 处理 |
|---|---|
| 版本改变 / 无法创建分身 | 运行 `python3 scripts/preflight.py` 查看自动兼容探测的失败项；保留原数据，等待适配，不绕过检查 |
| 额度 unknown / error | 在目标确认已登录并检查网络，再刷新；不要当作有可用额度 |
| 浏览器 Unauthorized | 用启动器或菜单栏重新打开面板；服务重启后旧页面令牌可能失效 |
| 新分身仍是旧聊天 | 退出目标、统一同步、重开；检查待同步、不支持或未结束回合 |
| 部分旧聊天为空 | 已知分页兼容限制；保留源历史，不删除源实例以“重新同步” |
| 置顶或排序异常 | 先退出目标，保留备份并报告版本与脱敏复现；不要手改运行中数据库 |
| 已关窗口仍提示运行 | 窗口关闭不等于进程退出，请在目标应用选择退出 |
| 切到新窗口后原任务还在运行 | 这是预期行为，任务没有迁移或被停止 |
| 菜单栏退出后仍有查询 | 退出菜单入口不会停止后台服务 |

## 删除与恢复

先在目标分身按 ⌘Q 退出，再点击卡片的“删除分身”并确认。原实例不可删除；运行状态不明时也会拒绝操作。删除期间与历史同步、创建和配置修改互斥。

旧版 `.runtime/clones` 分身的数据移到 `.runtime/deleted-clones/<分身编号>-<随机标识>/`；新分身的数据移到 `~/.codex-shadow/deleted-clones/<分身编号>-<随机标识>/`。同名 `.json` 恢复记录保存原目录、注册信息与删除状态。成功删除显示 `deleted`；操作失败时会尝试回滚，无法自动回滚则标记 `recovery_required` 并显示数据位置。不要删除失败时留下的目录或恢复记录。

目前恢复需要手动协助：保留整个私有备份，先停止管理服务并确认目标未运行，再根据恢复记录移回原目录并恢复注册项。恢复前核对原目录和编号未被占用；不要覆盖当前数据或编辑运行中的数据库。恢复记录含本机信息，应只在本机处理。删除不会清除已汇总到其他实例或历史 hub 的副本，也不会立即释放备份占用的磁盘空间。

## 软件更新

从 v0.3.0 起自动检查公开 GitHub 版本清单，每 6 小时一次；手动“检查更新”可立即重试。失败提示与额度错误分开，检查不需要账号凭据。新版提示只提供查看与安装入口，不静默替换代码。

按 [README 更新步骤](../README.md#更新到最新版) 拉取代码、预检与测试，再运行 `python3 launch_shadow.py`；启动器发现后台管理服务仍是旧版本时会自动安全重载，也可以显式使用 `--restart`。更新过程中应等待创建或同步完成，不再发起新的同步。启动器只重载本项目管理服务及菜单栏，保留 Codex 分身。早于 v0.3.0 的安装需要先手动升级一次。

## 停止与移除

目前未提供统一卸载器或后台停止按钮。关闭面板不会停止监控，退出菜单也不会结束桌面实例。需要完全停止时，可用“活动监视器”核对本仓库 `shadow_clones.py serve` 的 Python 进程并正常退出，只结束已核实的管理服务，不使用 `killall` 结束其他 Python 或 Codex 任务。

确认各分身已退出后，可将整个项目目录保留为本机备份。`.runtime` 包含账号、聊天与配置，删除它将移除分身数据；不要把删除作为普通故障恢复手段。原实例 `~/.codex` 和共享项目代码不应删除。

## 目录与隐私

生成的数据包括仓库 `.runtime` 中的实例注册、访问令牌、Swift 构建缓存与原生菜单应用，以及 `~/.codex-shadow` 中新分身的账号、聊天和配置。历史与配置备份位于各分身的 `.shadow-backups` 等内部路径。两个目录都应当保持私有，不作为示例或附件发布。

管理器会在创建、同步和打开分身等产生备份的操作结束后，清理 `.shadow-backups` 中较旧且结构完整的版本。每个分身保留最新完整历史数据库备份，每条聊天保留最新旧文件；侧边栏、项目归属和插件市场配置备份各保留最新一份。旧版数字命名、无法识别或不完整的目录会保留供人工检查；`deleted-clones` 恢复归档和历史 hub 不在清理范围内。磁盘空间紧张时先检查这些独立归档，不要删除正在使用的 `codex-home`。

报告问题只需要操作步骤、版本、测试结果及脱敏错误。不要上传个人路径、账号邮箱、令牌、私人聊天或完整日志。

## 多实例历史汇总

在任意分身中完成任务后，使用面板或菜单栏的“统一同步历史”。此操作把各实例已结束的任务汇总，给已退出的实例补齐；正在运行的实例保留原状，退出后由监控重试。可以开启“定期汇总历史”，无需逐个指定来源。

同一任务分叉会作为独立副本保留，已有未完成尾部不会被截断。分页/祖先依赖型历史暂不支持多源合并，面板会计数；不要把 partial 状态理解为所有聊天已经完全同步。新增任务按已有项目目录匹配；目标缺少对应项目时会先显示在“最近”，项目与配置导入仍是单独操作。

来源不再固定为 Codex 1；配置和账号仍各自独立。配置的手动复制继续以原实例为源。
