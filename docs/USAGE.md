# 使用、排障与数据保留

## 第一次运行

按 [README](../README.md) 检查环境并运行离线测试，然后 `python3 launch_shadow.py`。原实例默认取 `~/.codex`。创建分身会复制项目入口与配置并导入本地历史，然后打开独立窗口；项目较多时需要等待，面板会显示工作进度。

各分身使用独立登录。第三方插件、MCP 服务的连接可能仍需要你在对应分身确认。多个窗口操作的是同一份项目代码，给并行任务划分不同文件或使用自行管理的 worktree。

## 更新快照

先确认目标分身没有进行中的任务，并从目标应用退出，再点击“更新历史快照”。应用仍运行时会拒绝修改。更新完成后重新打开目标，以读取最新数据库与侧边栏状态。

新增表示新导入的源任务，更新表示刷新已有快照；冲突保留表示目标已独立变化，未被源覆盖；失败表示源文件或依赖不满足导入条件。partial 是部分成功，不能当作完整备份。当前回合需要结束或中止后才进入下一次快照。

同步项目与配置是另一个操作，源配置优先，会备份覆盖前的目标配置。历史快照与配置同步不是持续同步，不会自动反向写回原实例。

## 常见情况

| 现象 | 处理 |
|---|---|
| 版本改变 / 无法创建分身 | 核对 README 的应用路径和精确版本；等待适配，不绕过检查 |
| 额度 unknown / error | 在目标确认已登录并检查网络，再刷新；不要当作有可用额度 |
| 浏览器 Unauthorized | 用启动器或菜单栏重新打开面板；服务重启后旧页面令牌可能失效 |
| 新分身仍是旧聊天 | 退出目标、更新快照、重开；检查是否有冲突或未结束回合 |
| 部分旧聊天为空 | 已知分页兼容限制；保留源历史，不删除源实例以“重新同步” |
| 置顶或排序异常 | 先退出目标，保留备份并报告版本与脱敏复现；不要手改运行中数据库 |
| 已关窗口仍提示运行 | 窗口关闭不等于进程退出，请在目标应用选择退出 |
| 切到新窗口后原任务还在运行 | 这是预期行为，任务没有迁移或被停止 |
| 菜单栏退出后仍有查询 | 退出菜单入口不会停止后台服务 |

## 停止与移除

目前未提供统一卸载器或后台停止按钮。关闭面板不会停止监控，退出菜单也不会结束桌面实例。需要完全停止时，可用“活动监视器”核对本仓库 `shadow_clones.py serve` 的 Python 进程并正常退出，只结束已核实的管理服务，不使用 `killall` 结束其他 Python 或 Codex 任务。

确认各分身已退出后，可将整个项目目录保留为本机备份。`.runtime` 包含账号、聊天与配置，删除它将移除分身数据；不要把删除作为普通故障恢复手段。原实例 `~/.codex` 和共享项目代码不应删除。

## 目录与隐私

生成的数据在仓库 `.runtime` 内，包括实例注册、访问令牌、分身目录、Swift 构建缓存与原生菜单应用。历史与配置备份位于各分身的 `.shadow-backups` 等内部路径。整个目录应当保持私有并被 Git 忽略，不作为示例或附件发布。

报告问题只需要操作步骤、版本、测试结果及脱敏错误。不要上传个人路径、账号邮箱、令牌、私人聊天或完整日志。
