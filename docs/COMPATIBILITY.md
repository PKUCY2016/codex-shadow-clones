# 分身功能兼容性

分身运行同一个官方桌面应用，但使用独立的 Codex home 和 Electron 数据目录。
项目与配置可复制，不代表插件、账号授权、设备权限和宿主工具全部继承。

只读检查：

```sh
python3 scripts/check_clone_capabilities.py
```

该命令只返回配置状态和数量，不读取凭据、启动任务或修改实例。
配置中的 enabled 不能替代真实工具调用验证。

| 功能 | 当前边界与处理方式 |
| --- | --- |
| 代码、终端、模型对话 | 使用官方应用；各账号可用模型和额度分别决定，不合并订阅。 |
| 项目与 skills | 配置导入会复制项目入口、skills 和 rules；项目代码仍共享。 |
| 历史记录 | 使用已结束回合快照；运行实例延后写入，同一任务的分叉保留为副本。 |
| 任务间对话、任务管理 | 依赖宿主提供的 app-tools bridge 和实际工具暴露。每个桌面进程创建自己的 bridge；启动器清除父任务端点和身份。工具目录可见也不等于调用已落到正确实例。 |
| Computer Use | 同时检查顶层 node_repl 和 unified-computer-use 插件内的 cua_repl 配置。顶层缺少 sky 不代表插件内也缺；最终还依赖账号、运行服务及 macOS 授权。 |
| 浏览器与 Chrome | 插件配置可存在，但独立 Electron 目录不继承网站登录；Chrome 扩展连接需要单独验证。 |
| 第三方插件 | 登录和授权不随账号快照复制。需在目标实例连接；不能根据缓存目录存在宣称可用。 |
| 定时任务 | 新分身复制自动化定义为 **PAUSED** 模板，保留提示词和计划但不重复执行；在目标实例确认后单独启用。 |
| 记忆 | 新分身复制本地 Markdown/JSONL 记忆快照，跳过隐藏 git 存储；之后各实例独立写入，不做无冲突实时合并。 |
| 通知、语音、远程控制 | 需要各自运行服务、设备权限或设备登记，尚未完成跨实例验收。 |
| 本地 daemon 控制 | 新分身使用短物理 home；旧深层分身仍可能超过 macOS Unix socket 地址长度。该通道与桌面 app-tools bridge 不同，不能把旧 daemon 错误当作所有任务工具缺失的唯一原因。 |

## 已修复的配置复制问题

官方桌面会在各自 home 的 `.tmp/bundled-marketplaces/openai-bundled` 创建内置
插件市场。直接复制原实例的市场 source 会留下另一个 home 的临时路径，触发
“同名市场来自不同来源”错误，阻断内置插件协调。

配置复制现在移除这个由桌面管理的市场注册，保留插件开关、第三方市场和其余
偏好，让目标桌面自行重新注册。对已有分身，管理器只在确认目标退出后的下一次
打开前检查并修复这一项；修改前备份配置，运行目标只聚焦，不写配置。
修复记录位于目标 home 的 `.shadow-backups/desktop-marketplace-*`。
它不重登账号，不复制系统授权，也不承诺账号可用功能与原实例相同。

官方应用启动时会丢弃继承的 `CODEX_APP_TOOLS_PIPE_PATH` 并创建自己的端点。
本项目不再转发父实例的 bridge；同一 macOS 用户拥有 socket 并不能证明它属于
目标实例。启动环境也清除父任务的 thread/session 标识。

## 验证范围

本轮已用官方 CLI 在临时 home 复现同名市场冲突，并验证移除继承注册后可加入
目标自己的市场。随后在用户授权的真实分身中完成退出、配置备份、修复及重开：
市场来源变为目标自己的目录，官方日志确认内置插件安装与协调成功，Computer Use
的 sky 服务配置重新出现；其他桌面进程和各账号凭据均未变化。脱敏诊断区分
`foreign_runtime` / `target_runtime` / `not_registered`，不输出实际服务地址。

随后在获准重启的 Codex 3 实例中，通过 Computer Use 原生入口成功取得一次截图，
并通过原生任务工具完成只读列表与单任务读回；这证明该实例的实际调用链可用，
不等于所有新账号、系统权限或第三方连接都已验收。独立脚本的 bridge 探测未通过
官方父进程签名校验，不能替代桌面任务验收，也不能据此报告“工具已恢复”或“桌面工具损坏”。
配置中的 enabled、服务声明或缓存目录存在均不能替代此验收。

## 默认 daemon 路径

新建分身默认使用 `~/.codex-shadow/<编号>/` 作为物理 home，并把项目注册表继续
放在仓库的私有 `.runtime/`。这样默认 daemon socket 不再拼接深层仓库路径；旧版
已经存在于 `.runtime/clones/` 的分身仍按旧路径运行和删除。可通过
`CODEX_SHADOW_PROFILE_ROOT` 指定其他物理根目录，管理器会拒绝受管目录之外的
路径和符号链接。诊断同时报告实际 UTF-8 字节数和端点是否存在，两者不是同一故障。
桌面 app-tools 使用另一条通道。

Computer Use 的官方设置入口为 Plugins → Computer Use；按系统提示完成
屏幕录制和辅助功能授权，第三方插件仍需在各实例独立连接。
[官方说明](https://learn.chatgpt.com/docs/computer-use)
